# 🗑️ ИМПЛЕМЕНТАЦИЯ МЯГКОГО УДАЛЕНИЯ

## 📋 ОСНОВНЫЕ ПРИНЦИПЫ

### 1. **Поле `deleted_at` в таблице**
```sql
ALTER TABLE users ADD COLUMN deleted_at TIMESTAMP NULL DEFAULT NULL;
```

### 2. **Трейт SoftDeletes в модели**
```php
use Illuminate\Database\Eloquent\SoftDeletes;

class User extends Model
{
    use SoftDeletes;
}
```

### 3. **Типы внешних ключей (ON DELETE)**

|Тип |Когда использовать |Пример |
|:-:|:-:|:-:|
|SET NULL|Когда нужно сохранить запись, но обнулить ссылку |assignments.created_by |
|CASCADE |Когда дочерние записи должны удаляться вместе с родителем |user_specialties.user_id |
|RESTRICT |Когда удаление родителя должно быть запрещено пока есть связи |Важные бизнес-данные |
|NO ACTION |Стандартное поведение, аналогично RESTRICT |Большинство связей |

## 💡 КЛЮЧЕВОЕ ПОНИМАНИЕ: МЯГКОЕ УДАЛЕНИЕ ≠ УДАЛЕНИЕ

### ОШИБОЧНАЯ ЛОГИКА:
"Удаляем запись → связи становятся NULL"

### ПРАВИЛЬНАЯ ЛОГИКА:
"Архивируем запись (deleted_at) → связи сохраняются → запись скрыта из UI"

### КАК ЭТО РАБОТАЕТ:
1. **В БД**: UPDATE table SET deleted_at = NOW() WHERE id = X
2. **Связи**: Остаются неизменными (внешние ключи валидны)
3. **Laravel**: По умолчанию исключает записи с deleted_at != NULL
4. **Доступ**: Можно получить через withTrashed() или onlyTrashed()

### НАСТРОЙКА ВНЕШНИХ КЛЮЧЕЙ:
- ВСЕ FK: ON DELETE NO ACTION (запрет физического удаления)
- ВСЕ FK: ON UPDATE NO ACTION (запрет изменения ID)
- Мягкое удаление обходит эти ограничения (не использует DELETE)

## 🚀 СТРАТЕГИЯ ВНЕДРЕНИЯ

### ПРИНЦИПЫ:
1. **Историческая целостность** - никогда не терять связи между данными
2. **Безопасность удаления** - каждая операция удаления проверяется
3. **Восстанавливаемость** - любую операцию можно отменить
4. **Прозрачность** - пользователь всегда видит, что запись удалена

### ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ:
1. **Все ключевые модели** используют `SoftDeletes` трейт
2. **Все внешние ключи** используют `ON DELETE NO ACTION`
3. **Каскадное удаление** реализуется через события Eloquent
4. **Проверки бизнес-логики** предотвращают некорректные удаления

### ИНТЕРФЕЙС:
1. **Filament Resources** имеют действия: удалить/восстановить/уничтожить
2. **Фильтры** для отображения удаленных записей
3. **Предупреждения** при попытке удалить связанные данные
4. **Логирование** всех операций удаления
